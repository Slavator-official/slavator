# Аудит и Windows-план Славатора

Проверены архитектура, Python-ядро, SwiftUI- и Tk-интерфейсы,
хранение данных, сборка, установка и тесты.

## Что исправлено в Windows-ветке

- Вымышленные встречи и люди больше не выдаются за данные пользователя.
- Папка результа была настройкой только на экране: запись и история
  всё равно искали `Downloads`. Теперь путь единый.
- Tk запускал старое ядро из случайной папки. Windows-запускатель жёстко
  связывает его с актуальным `core/meeting_transcriber_v25_1.py`.
- Воспроизведение было привязано к macOS-команде `afplay` и POSIX-сигналам.
  Для Windows добавлен изолированный WAV-плеер.
- Длительность WAV считалась внешним `ffprobe`, которого нет ни в лёгкой
  macOS-сборке, ни в Windows-установщике. Теперь WAV читает стандартная библиотека.
- Повреждённый `profiles.json` ронял весь интерфейс. Теперь данные можно
  восстановить, не блокируя запуск.
- Сетевой tar-архив модели распаковывался без проверки путей. Добавлен
  безопасный фильтр извлечения.
- Два файла тестов искали GUI на каталог выше и не могли даже собраться.
  Пути исправлены; добавлен Windows CI.

## Оставшиеся риски

### Высокий приоритет

1. **Нужен smoke-test на чистой Windows 10 и Windows 11.** CI проверит код и
   PowerShell, но не может честно проверить микрофон, драйвер звука, ярлык и
   многочасовую запись.
2. **Нет полного паритета с macOS.** В Windows-ветке пока нет системного
   WASAPI-loopback, глобальной диктовки и чата. Обработка файлов, микрофон,
   диаризация, профили и резюме работают.
3. **Скачиваемые ONNX-модели не проверяются по SHA-256.** HTTPS и безопасная
   распаковка снижают риск, но для воспроизводимой цепочки поставки нужны хэши.

### Средний приоритет

1. Пороги опознания голоса выведены по 22 образцам семи людей, а порог
   диаризации — по нескольким записям. Нужен обезличенный набор разных
   микрофонов, языков, шумов и размеров встреч.
2. Запись `profiles.json` и `voice_assignments.json` атомарна, но не защищена от
   одновременной записи GUI, виджетом и ядром. Нужна межпроцессная блокировка.
3. Tk-окно показывает прогресс в заголовке окна, а не полную панель с паузой,
   отменой и понятным текстом ошибки, как SwiftUI-версия.
4. Нет end-to-end теста на маленьком аудиофайле с заранее известным текстом
   и двумя голосами. Сейчас тесты в основном проверяют контракты и метаданные.

## Рекомендуемый следующий этап

Сначала прогнать установку и 10-минутную запись на чистой Windows 11. После этого
добавить WASAPI-loopback в тот же WAV-поток, которым уже пользуется виджет. Так не
появится третий пайплайн распознавания.
