# Память встреч: рабочая локальная версия

Вкладка «Спикеры» теперь читает реальные `transcript.json` из выбранной
папки результатов. Демо-данные для работы не нужны. Изменения не опубликованы.

## Что можно проверить

- «Поиск и история»: фраза или описание контекста; фильтры человека и встречи.
- «Точная фраза»: слова подряд, без учёта регистра, пунктуации и ё/е.
- «По смыслу»: локальные векторы EmbeddingGemma плюс лексическое ранжирование.
  Выдача — исходные цитаты, а не сгенерированный ответ. Близость по смыслу
  не доказывает, что цитата отвечает на вопрос: открывайте контекст.
- Цитата содержит встречу, говорящего, время от начала записи и дату обработки.
  Дата обработки не выдаётся за дату самой встречи.
- «Открыть контекст»: соседние реплики, документ расшифровки и папка встречи.
  На Mac можно слушать фрагмент исходного аудио, включая WebM/MKV через PyAV.
  Если оригинал удалён или перемещён, текст остаётся доступен.
- «Уточнить, кто говорит»: ручная привязка всех реплик конкретного голоса
  в этой встрече к существующему профилю. Новые профили создаются через «Новые голоса».
- «Граф встреч»: линия означает совместное присутствие голосов в сохранённой
  встрече. Нажатие на человека открывает его окружение; список связей раскрывает
  конкретные встречи-основания. Это не социальный граф отношений или выводов ИИ.
- По умолчанию граф показывает подтверждённых людей. Все остальные доступны
  через «Показать неопознанные голоса» и отдельный список для уточнения имён.
  Назначение профиля обновляет память при возвращении на экран без минутной задержки.
- Одиночные служебные обрывки («как», «ну вот») не становятся самостоятельными
  результатами поиска и не индексируются по смыслу. Они остаются в контексте
  и исходной стенограмме. Короткие ответы «да», «нет», числа и аббревиатуры сохраняются.

## Граф по выбору и чат

На вкладке графа есть «Строить граф встреч». Выключение прекращает вычисление
связей; поиск, история и чат продолжают работать.

В Mac-чате включите «Искать в памяти встреч». Для вопросов «когда я говорил…»
выберите свой профиль в «Ваш голос». Ответ содержит исходные цитаты, кнопки
прослушивания и контекста. При недоступной модели остаётся выдача цитат.
Смысловое совпадение может быть приблизительным — проверяйте первоисточник.
Дата обработки не является датой разговора.

Новый режим обращается только к локальной Ollama без прокси и перенаправлений.
Переписка, однажды включившая память, не отправляется на удалённый адрес даже
после выключения переключателя. Цитаты, уже сохранённые в переписке, остаются
частью чата после удаления встречи; сам чат можно удалить отдельно.

## Удаление и восстановление

В карточке записи доступно «Слушать запись». Нижняя панель позволяет
перематывать по полосе и на 15 секунд, ставить паузу и выбирать скорость 0,5–2×.
У записанных звонков отдельная микрофонная дорожка звучит синхронно с основной.
Если исходный файл отсутствует, кнопка недоступна; стенограмма остаётся доступной.

В «Записях» у встречи есть кнопка «Удалить». После подтверждения **все версии
этой встречи** перемещаются в `.slavator-trash` внутри выбранной папки результатов.
Это корзина Славатора, не системная корзина. Исходное аудио вне папок результатов
и глобальные голосовые профили не удаляются. Поиск, векторы и граф перестраиваются
без удалённой встречи; старый архив не появляется вместо неё.

Меню «Корзина Славатора» позволяет восстановить встречу, в том числе после
перезапуска приложения. Если её место уже занято новой обработкой, восстановление
останавливается без перезаписи. Можно открыть папку корзины для ручного восстановления.
На Windows/Tk эти действия находятся в «Память встреч → Встречи и корзина».
Удаление отключено во время обработки. Это обратимое удаление из библиотеки,
**не гарантированное уничтожение конфиденциальных данных на диске**.

## Как сохраняется память

Источник истины — файлы встреч и профилей. SQLite находится в папке данных
приложения, в `memory/`. Для каждой папки результатов создаётся отдельный индекс.
Он сохраняется между запусками; смена модели векторов требует их пересчёта.
Изменившиеся файлы перечитываются, удалённые результаты исключаются из индекса.
Повреждённая запись не заменяет последнюю успешно прочитанную версию: интерфейс
показывает предупреждение. Недоступная папка не очищает существующую память.

«Обновить память» синхронизирует текст и недостающие смысловые векторы.
Обновление также запускается при каждом входе во вкладку и после изменения
профилей на ней. Поиск сверяет текстовые изменения перед запросом.
Остановка не теряет уже зафиксированные пакеты; можно продолжить обновление.

Соседние отрезки одного голоса объединяются в фрагменты до минуты / 900 символов.
На проверенных данных 678 исходных отрезков образовали 162 поисковых фрагмента;
исходные расшифровки не изменены. Теперь в поиске и графе участвует только актуальная
версия каждой встречи, как в списке записей. Каноническая папка `<имя>_result`
приоритетнее архивов `<имя>_<дата>_<время>_result`, даже если у архива свежее время
изменения. Сами архивные файлы остаются на диске до удаления встречи.

Ручные привязки находятся в `speaker_links.json` внутри дополнительных файлов
встречи. Опознание голосом использует `profile_key` из `speaker_recognition.json`.
Имя, угаданное по контексту, не объединяет людей между встречами. Совпадающие
имена разных профилей также не склеиваются. Неуверенно размеченные реплики
нового конвейера не добавляют вымышленных участников в граф.

## Платформы и ограничения

SwiftUI и Windows/Tk используют один `core/speaker_memory.py`, формат данных
и индекс. В Windows вход — «Спикеры → Память встреч»: поиск, контекст и граф.
Нативный Mac-интерфейс дополнительно позволяет слушать цитаты и уточнять
личность из карточки контекста. Полное совпадение интерфейсов не заявляется.
Tk-клиент запускался на Mac, но ещё требует проверки на настоящей Windows.
Общее ядро подходит для Ubuntu; готового Ubuntu-дистрибутива пока нет.

Без Ollama доступны история, граф и поиск по фразе. Если смысловая модель
недоступна, интерфейс явно сообщает о переходе к совпадениям слов. На проверяемом
Mac модель уже установлена. В закрытый контур её нужно доставить заранее,
через согласованный с ИБ офлайн-комплект, а не скачивать при работе.

Индекс содержит текст встреч в открытом виде. Это рабочая функция, но не
сертифицированный защищённый продукт: права доступа, шифрование, сроки хранения,
контроль сетевой активности и упаковка для ИС требуют отдельного согласования.
Предложение по архитектуре находится в `docs/hardening/`.
Оно привязано к более раннему снимку исходников; перед архитектурной миграцией
нужно сверить изменения, включая новую корзину и правила индексирования.

## Проверки

Автоматические проверки покрывают старые настройки, индексирование реальной
схемы, кириллицу, пересчёт моделей, пропавшие/повреждённые файлы, атомарность
записи, разные профили с одним именем, ручные привязки, пагинацию, отмену,
контекст и подготовку аудио. Отдельный интеграционный тест вызывает настоящую
локальную модель на русских перефразировках, без интернет-запросов.

Модель и API: [EmbeddingGemma](https://ollama.com/library/embeddinggemma),
[Ollama embeddings](https://docs.ollama.com/api/embed).
