# Славатор

Расшифровка рабочих встреч на Mac. По умолчанию распознавание и языковая
модель работают на вашем компьютере. Если вручную указать внешний сервер
Ollama, текст для резюме, обычного чата и обработки диктовки отправляется
туда — напрямую, мимо системного прокси и без перенаправлений. Чат по памяти
встреч и переписки с цитатами остаются локальными.

Что умеет:

- расшифровывает записи встреч и разделяет речь по голосам;
- узнаёт людей по голосу и предлагает имя, вычитанное из разговора;
- записывает живой звонок: собеседников со звука компьютера, вас с
  микрофона — в один файл;
- диктует в любое текстовое поле по удержанию правого <kbd>⌥</kbd>;
- собирает резюме, решения и поручения — по кнопке, когда нужно;
- хранит память встреч: поиск по фразе и смыслу, цитаты с временем, история
  человека и отключаемый граф совместных встреч — пока только в тестовой
  сборке;
- отвечает по памяти встреч со ссылками на исходные реплики — там же;
- проигрывает полную запись с перемоткой и скоростью от 0,5× до 2×.

Меню слева: «Главная», «Память встреч» (в тестовой), «Записи», «Спикеры», «Настройки».

## Ollama

Языковая модель работает через локальную Ollama. Славатор поднимает её сам
при запуске — только сервер, модель ложится в память при первом запросе —
и она работает дальше, даже когда Славатор закрыт. Ollama из Homebrew
после перезагрузки сама не стартует, и без этого резюме, имена и
обработка диктовки молча не работали. Внешний адрес Ollama Славатор не
запускает.

## Какой Mac нужен

- процессор Apple M1 или новее: на Mac с Intel программа не запустится;
- macOS 14.2 или новее;
- около 10 ГБ на диске и интернет при первой настройке.

Выпуски собираются только для Mac. Windows-часть живёт в ветке `windows`
(запускатель и установщик — в [`windows/`](windows/README.md)), в образ для
Mac она не входит.

## Установка из выпуска

Репозиторий закрытый: скачать образ может только тот, у кого есть доступ.

1. Скачайте `Slavator-0.13.0-macOS-arm64.dmg` со страницы выпуска, откройте
   и перетащите «Славатор» в «Программы».
2. У программы нет подписи Apple, поэтому снимите отметку «скачано из
   интернета»:

   ```bash
   xattr -dr com.apple.quarantine /Applications/Славатор.app
   ```

   Другой путь: попробовать открыть, затем Системные настройки →
   Конфиденциальность и безопасность → «Открыть всё равно».
3. Откройте Славатор и нажмите «Установить». Откроется Терминал и поставит
   Python, распознавание, разделение голосов и Ollama: около 6 ГБ, 20–40
   минут, один раз.

Подробная инструкция для пользователя лежит в образе —
[`packaging/ПРОЧТИ_МЕНЯ.txt`](packaging/ПРОЧТИ_МЕНЯ.txt): разрешения,
первая запись, словарь терминов, где журнал и как переустановить.

Если GitHub недоступен и Ollama не скачалась, расшифровка и разделение по
голосам всё равно работают; языковая модель нужна для резюме и имён. Для
такого случая есть полный образ `Славатор-полный.dmg` с Ollama и моделью
внутри — он собирается `packaging/make_dmg.sh --full` и в выпуск на GitHub
не выкладывается.

### Модели

Выбираются в настройках списком; в нём видно, что уже скачано, сколько весит
и чем отличается. Подходящая машине помечена «рекомендуем» и выбрана при
первом запуске — по объёму оперативной памяти:

| Память | Распознавание | Языковая модель |
|---|---|---|
| до 10 ГБ | `small` | `qwen3:1.7b` |
| 10–17 ГБ | `large-v3-turbo` | `qwen3:4b` |
| 18 ГБ и больше | `large-v3` | `qwen3:8b` |

Установщик качает языковую модель по тем же ступеням, а распознавание ставит
на `small`; более точную модель выбирают в настройках. Ступени заданы в
`ModelCatalog` (`app/Configuration.swift`) и продублированы в
`packaging/setup.command` — менять вместе. Замер ресурсов распознавания:
`docs/benchmarks/`.

## Как устроено

Две части, связанные через запуск подпроцесса и построчный обмен по stdout.

| Каталог | Что там |
|---|---|
| `app/` | Интерфейс на SwiftUI. Собирается `swiftc` из Command Line Tools, Xcode не нужен |
| `core/` | Обработка на Python: распознавание, разделение голосов, память встреч, документы |
| `packaging/` | Сборка бандла, образа, установщик и «ПРОЧТИ МЕНЯ» для образа |
| `docs/` | Обзоры, аудиты, память встреч, бэклог |
| `windows/` | Windows-запускатель и PowerShell-установщик, в сборку для Mac не входят |
| `legacy/` | Tk-интерфейс: не участвует в macOS-сборке, используется Windows-веткой |

Ядро печатает в stdout человеческие строки и машинные `@@PROGRESS@@`;
приложение читает их и рисует ход работы. Диктовка общается с отдельным
постоянным процессом (`core/dictation_worker.py`) построчным JSON в обе
стороны — модель держится в памяти, иначе на каждую фразу уходили бы секунды
на её загрузку.

Общие значения настроек и основные цвета находятся в
`core/desktop_contract.json`. Python-клиенты используют `core/app_config.py`,
SwiftUI — `app/Configuration.swift`. Старые поля настроек сохраняются при
обновлении и переключении интерфейса. Приоритет настроек обработки:
явное окружение → выбор в `settings.json` → `config.env` → значения по умолчанию.
Профили голосов лежат в `~/whisper-work`, окружение и настройки — в
`~/Library/Application Support/Славатор`.

Документы:

- [память встреч](docs/ПАМЯТЬ_ВСТРЕЧ.md) — поиск, граф, чат с цитатами;
- [обзор изменений 7 сентября](docs/ОБЗОР_2026-09-07.md) и
  [объединение веток 8 сентября](docs/ОБЪЕДИНЕНИЕ_2026-09-08.md);
- [аудит безопасности 16 сентября](docs/АУДИТ_БЕЗОПАСНОСТИ_2026-09-16.md);
- [практики Meetily](docs/MEETILY_ПРАКТИКИ.md) — что у конкурента хорошо и что взято;
- [сравнение офлайн-архитектур](docs/hardening/hardening.md) для закрытой ИС.
  Это предложение, а не выполненная миграция: установщик требует интернет,
  общего запрета внешних соединений пока нет.

`packaging/Предпросмотр.command` — отдельный запуск для проверки дизайна на
вымышленных данных, для работы с настоящими встречами не нужен.

### Стек

- **faster-whisper** (CTranslate2, без torch) — распознавание речи
- **sherpa-onnx** — разделение голосов, отпечатки голоса, детектор речи
- **Ollama + qwen3** (1.7b / 4b / 8b) — резюме, определение имён, чат,
  обработка надиктованного
- **SQLite + FTS** — память встреч
- **SwiftUI + AppKit** — интерфейс

Текущая установка не требует пользовательских токенов для загрузки используемых
артефактов. Для корпоративной поставки лицензии библиотек и каждого набора весов
нужно проверить отдельно: доступность скачивания не заменяет эту проверку.

## Сборка

```bash
packaging/build_app.sh           # тестовая «Славатор Dev» — из папки как есть
packaging/build_stable.sh        # основная «Славатор» — из коммита (HEAD или тег)
packaging/make_dmg.sh            # лёгкий образ (~2–3 МБ) из основной, всё качается при установке
packaging/make_dmg.sh --full     # полный (~5,5 ГБ): Ollama и языковая модель внутри
```

Сборка кладёт бандл в `packaging/dist.noindex/` и ставит его в
«Программы», закрывая и поднимая заново только свою сборку. Нужны
macOS 14.2+ на Apple Silicon и Command Line Tools, полный Xcode — нет.

### Две сборки на одной машине

| | Основная | Тестовая |
|---|---|---|
| Название | «Славатор» | «Славатор Dev» |
| Иконка | исходная | синяя с плашкой DEV |
| Идентификатор | `ru.slavator.app` | `ru.slavator.app.dev` |
| Собирается | `build_stable.sh` — из коммита | `build_app.sh` — из папки как есть |
| Память встреч | нет, пока не докрутили | есть |
| Parakeet в диктовке | нет | есть |
| Восстановление записи после падения | нет | есть |

Тестовая по умолчанию, чтобы пробная сборка не заменяла ту, которой
работают. Основная собирается только из коммита: в папке лежит
недоделанное, и ему место в тестовой. Пока основная запущена, тестовая выключает у себя диктовку,
виджет, значок в меню и слежение за встречами; закрыли основную — всё
включается по настройкам. Проверить диктовку или виджет тестовой можно,
только закрыв основную.

Память встреч в боевой выключена флагом `Edition.hasMemory`
(`app/Configuration.swift`): нет пункта меню, режима «по памяти» в чате и
истории человека в карточке спикера. Корзина записей работает в обеих.

Встречи, голоса, настройки и Python-окружение у сборок общие. Разрешения
macOS (микрофон, ввод, звук системы) тестовая просит отдельно: для системы
это другое приложение.

Проверки без загрузки моделей:

```bash
python -m pytest -q core/tests legacy/tk-версия/test_v25_10.py legacy/tk-версия/test_gui_flows_v25_10.py legacy/tk-версия/test_ui_contract_v25_10.py
bash packaging/test_swift.sh
```

### Проверка после каждой сборки

Две вещи ломались молча и стоили дня работы, поэтому проверяются всегда:

```bash
otool -L packaging/dist.noindex/Славатор.app/Contents/MacOS/slavator | grep -c SwiftUICore   # 0
codesign --verify packaging/dist.noindex/Славатор.app                                        # valid
```

`SwiftUICore` — фреймворк из macOS 15. Если линковщик его пропишет,
приложение не запустится на macOS 14 вовсе: падение при старте, без окна.
Тянут его `.fixedSize()`, свои раскладки на протоколе `Layout` и `.tag()`
в `Picker` — эти три вещи в коде не использовать. Сборка отклоняет его
появление сама, но проверка выше дешевле, чем разбор упавшего запуска.

Подпись ломается, если Python успевает записать `__pycache__` внутрь бандла.
Вместе с подписью слетают выданные разрешения — микрофон и управление вводом.
Поэтому ядро запускается с `-B` и `PYTHONDONTWRITEBYTECODE=1`.

## Версии

Номер версии один на весь проект и лежит в файле `VERSION` в корне. Оттуда
его берут и сборка (штампует в манифест приложения), и ядро.

Нумерация по [семантическому версионированию](https://semver.org/lang/ru/):
`МАЖОРНАЯ.МИНОРНАЯ.ПАТЧ`. Меняем мажорную — когда ломается совместимость
данных или настроек; минорную — когда добавилась возможность; патч — когда
только починили.

Выпуск версии:

```bash
echo "0.14.0" > VERSION
# перенести «Не выпущено» в CHANGELOG.md, раздел [0.14.0] с датой
git commit -am "Версия 0.14.0"
git tag -a v0.14.0 -m "Версия 0.14.0"
git push && git push --tags
packaging/build_stable.sh && packaging/make_dmg.sh
cp packaging/dist.noindex/Славатор.dmg Slavator-0.14.0-macOS-arm64.dmg
shasum -a 256 Slavator-0.14.0-macOS-arm64.dmg   # вписать в описание выпуска
gh release create v0.14.0 Slavator-0.14.0-macOS-arm64.dmg --title "Славатор 0.14.0 для macOS"
```

Что изменилось между версиями — в [CHANGELOG.md](CHANGELOG.md).

## Работа вдвоём

### Развернуть у себя

```bash
git clone git@github.com:Slavator-official/slavator.git slavator
cd slavator
git switch slava/mac                               # самое свежее; ios/macbook — после слияния
packaging/build_stable.sh                          # соберёт и поставит Славатор.app
open /Applications/Славатор.app                    # дальше кнопка «Установить»
```

Первый запуск предложит развернуть окружение: Python, модели распознавания,
Ollama. Около 6 ГБ и 20–40 минут, один раз.

Разработчику образ не нужен: собранное у себя приложение не помечается
карантином, поэтому не будет ни окна «Apple не удалось подтвердить», ни
команды `xattr` — эта морока бывает только у файлов, пришедших из интернета.

Подписывается сборка временной подписью. Единственное следствие: после каждой
пересборки macOS заново спросит доступ к микрофону и к вводу, потому что
считает приложение новым. Если правите только питоновскую часть в `core/`,
пересборка не нужна вовсе — там достаточно запустить `python`.

### Ветки

- `ios/macbook` — основная ветка репозитория, её видно на GitHub первой.
  Название не означает поддержку iPhone: здесь собирается приложение для macOS.
- `slava/mac` — текущая работа над Mac; из неё собран выпуск 0.13.0. В
  `ios/macbook` попадает через pull request.
- `windows` и `ubuntu` — версии для других систем, ведутся отдельно.
- Ветка на задачу: `feature/диктовка`, `fix/подпись-бандла`.
- Слияние через pull request, чтобы изменение кто-то прочитал.

Правило про комментарии: объяснять **почему**, а не что. Половина неочевидных
решений в этом коде — следы конкретных поломок, и без объяснения следующий
человек их «починит» обратно.

## Чего в репозитории нет и не будет

**Голосовых профилей.** Это биометрия живых людей, и доступ к репозиторию
шире, чем их согласие. `transfer/`, `*.npy` и `speaker_profiles/` закрыты
в `.gitignore` намеренно.

**Записей встреч, стенограмм и словаря терминов** — там рабочее содержимое.

**Моделей, образов и архивов** — гигабайты в git не кладут. Образы
выкладываются в выпуски на GitHub, а не в репозиторий.
